# RULA 結案修正版：共同頸部分數與局部人工確認

此版以「RULA 結案整理版」完整 `222.py` 為基底，只收斂頸部計分和使用者報表；保留三鏡頭同步、Pose+Hand（Hand 2D 優先、Pose 2D 備援）、骨架品質與遮擋診斷、剔除／一般提醒分流、逐影格人工評分、作業基本資料、ZIP 自動命名等功能。

## 頸部處理方式

同一時間點，左右兩側若都能成功分析，就只採 **一個共用的 RULA 頸部分數**（包含既有補正）。不再讓左右上肢分別使用不同頸部分數進行最終評估。

- 左右分數相同：直接共用，沒有多餘人工操作。
- 左右分數不同，但分別使用兩個候選頸分計算出的**完整雙側最高分的 AL 行動等級相同**：保守採用較高頸分，並在技術診斷記錄這項折衷；不宣稱較高角度是真值。
- 左右分數不同，且有可能改變完整雙側 AL：將該時間點標記「待頸部人工確認」。自動 Grand Score 是候選值，**在確認前不列入可信統計**。
- 只有一側成功分析：保留可用單側，但不能冒充完整雙側最高分；不強行共用頸分。

### 使用者如何確認頸部

分析完成後，進入 **「角度檢視 → 頸部」**，或「剔除樣本 → 需要頸部分級確認」。使用者選擇這筆影格的頸部前屈等級／後仰，並勾選是否扭轉、側彎，按 **「確認此筆頸部分數並重新計算雙側」**。系統只改這筆的**共同頸分**，左右側其他部位沿用原自動／人工分數；「風險總覽」及「複核後結果」會立即重新查表。

*原始分析 CSV、角度及候選分數不被覆蓋。* 若影格因其他關鍵點／遮擋品質原因另列入人工複核，該項仍須單獨處理；確認頸部並不等於確認其他部位。

## 一般報表與技術追溯

- `評估結果/`：只顯示 **共同頸部分數、確認狀態**及其他部位採用角度／分數，不再在使用者報表顯示各鏡頭頸角、舊公式或版本名稱。未確認時，相關候選 RULA 分數留空而非當正式分數。
- `複核後結果/逐側結果.csv`、`複核後結果/雙側結果.csv`：依頸部確認、人工修改、剔除等決定重算。`頸部分級確認.csv` 留下確認狀態。
- `技術診斷/頸部分級情境比對.csv`：保留左右原估角度／分數、兩個候選共用頸分各自產生的左右總分及雙側 AL；舊版／同側方法原角度資料仍保存在原有技術對照中。
- 日期、單位／部門、員工及作業名稱可在第一頁輸入，ZIP 檔名依資料自動生成。

## 部署

1. 解壓部署 ZIP，將資料夾**內**的 `222.py`、`requirements.txt`、`packages.txt` 以及 `models/`、`scripts/` 更新至 GitHub 儲存庫根目錄。`222.py` 必須是 Streamlit Cloud Main file path。
2. Streamlit Cloud **Python 3.11**。繼續使用 `mediapipe==0.10.21`，避免破壞舊版 `mp.solutions.pose`。
3. 需要 `models/hand_landmarker.task`。可使用 `scripts/download_hand_model.py` 取得官方檔案；模型未隨 ZIP 附入，程式也可嘗試下載到可寫入的暫存路徑。
4. 部署識別可從側邊欄「系統維護資訊」查閱：`RULA_SHARED_NECK_LOCAL_REVIEW_FINAL_2026-10-29`。

## 測試與限制

完整 Python 語法檢查及 `tests/` 中的離線純函式測試已執行（包括 RULA 查表情境、兩側共用、AL 敏感度、局部確認後重算、人工修正、剔除與 ZIP 複核輸出）；未在 Streamlit Cloud 使用真實影片完成端到端測試。單一攝影機 2D 頸部角度不是經校準的人體頸椎解剖角度；共同分數可改善**分數一致性及人工複核負擔**，**不代表**已驗證頸角精度。RULA Table A／B／C 對標準工作表的逐格獨立稽核仍待完成。

### 結案驗收建議

請使用同一組三視角影片重新分析，確認「角度檢視 → 頸部」的待處理數量、人工確認後左右側分數同步更新、風險總覽排除未確認影格、ZIP 中「複核後結果」與原始分數可追溯。若正常，可固定此版本並轉入人工參考角度和 RULA 工作表驗證。
