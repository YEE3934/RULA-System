# RULA 智慧姿勢評估系統｜正面鏡頭選填版

這份程式以先前已交付的「共同頸部分數／局部人工複核＋工廠雙側模式」為基礎，**把 Front 正面影片改成選填**，不需要再特別切到一個「工廠雙側模式」。其餘已建立的姿態計分、Hand 優先／Pose 2D 備援、左右共用頸部分數、必要時的局部人工複核、品質診斷、照片、作業資料與 ZIP 下載均保留。

## 評估模式與必填影片

| 評估模式 | 必須上傳 | 選填 |
|---|---|---|
| 右手側 | 右側影片 | 正面影片 |
| 左手側 | 左側影片 | 正面影片 |
| 左右側同步計算 | 右側＋左側影片 | 正面影片 |

**有正面影片時**：系統可依照「自動辨識設定」對上臂外展、前臂跨中線、前臂向外側工作、軀幹側彎、頸部側彎，使用正面影像作代理判斷（若取消自動判斷則用人工選項）。正面影片可以減少需要手動確認的項目，但**不代表角度必然更精準**，遮擋和關鍵點偏移仍可能影響結果。

**沒有正面影片時**：這五項正面補正會自動切換為人工確認，仍可繼續估測上臂／前臂／手腕／軀幹／頸部等側面適用項目。請到 **第 3 步「自動辨識設定」**，勾選選定評估側實際存在的補正；沒有勾選代表你已人工確認不存在，並按「我已確認所選側別的各項補正」。未確認時不能啟動分析。這些確認套用整段影片；如果姿勢中途改變，應逐影格複核。

## 時間同步

- 只用一支側面影片：不用做跨鏡頭同步，程式會使用該影片 0 秒為參考。
- 同時使用兩支或三支影片：進入第 2 步，預覽共同動作，調整影片各自的同步事件秒數並確認。可以不同 FPS、不同起錄時間與不同長度，只分析共同涵蓋區間。
- 沒有上傳 Front 時，CSV／ZIP 不會虛構正面影格；同步報表只列真正使用的鏡頭。

## GitHub 與 Streamlit Cloud 更新

1. 解壓部署包，把裡面的 `222.py`、`requirements.txt`、`packages.txt` 放在 GitHub 儲存庫的**根目錄**。
2. 保留現有 `models/hand_landmarker.task`；如果沒有模型檔，原程式保留下載到可寫入暫存目錄的備援機制，`scripts/download_hand_model.py` 可供參考。
3. Streamlit Community Cloud 的 Python 版本仍使用 **3.11**，Main file path 設為 `222.py`。
4. 部署後可在「系統維護資訊」確認程式標記 `RULA_OPTIONAL_FRONT_2026-10-29`。
5. 如果舊瀏覽器工作階段已經選了舊的「工廠雙側」或舊的「左右側三視角」模式，程式會自動轉成「左右側同步計算」；建議再檢查一次正面上傳狀態和人工補正設定。

## ZIP 匯出

- **雙側**：保留左右共同評分、左右側分開報表及相應品質複核資料。報告註明是否使用正面影片。
- **單側**：保留單側角度與 RULA 評分，報告也註明是否有正面影片；無正面時另外提供 `評估結果/無正面人工補正確認.csv`。
- 兩種模式都保留日期、單位、員工、作業名稱及自動檔名，也會保存各鏡頭實際取樣秒數和骨架品質診斷。

## 已測試的內容

- `python -m py_compile 222.py`
- `python tests/test_optional_front.py`：右單側／左單側／左右雙側 × 正面有／無，共六種必要鏡頭、同步、時間映射與分流。
- `python tests/test_optional_front_video.py`：以 OpenCV 製作不同 FPS 的合成影片，實際測試六種相機組合的抽幀。
- 既有共同頸部、手腕、品質複核、人工決策、精簡報表測試亦已執行。

**限制：** 這是離線程式及影片抽樣測試，並非已在 Streamlit Cloud 用真實工廠影片完成端到端驗收；模型量得出角度不代表一定符合人體解剖角度。RULA 查表矩陣仍應在正式報告前與選用的標準工作表核對。
