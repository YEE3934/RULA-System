# RULA v11｜骨架遮擋品質檢查、時序重查與跨視角提示

基於使用者成功部署的 **RULA v10.2 完整程式**，不是重新建立精簡版。保持現有三視角同步、Hand 2D 優先／Pose 2D 備援、RULA 評分、人工修正、頸部及手腕比較、時間軸、原圖／骨架圖、ZIP 下載與五步驟介面。

## 一、如何部署

1. 先備份你目前 GitHub 上可正常運行的 `222.py`。
2. 將本資料夾的 `222.py`、`requirements.txt`、`packages.txt` 上傳到 **GitHub 儲存庫根目錄**（不要多套一層資料夾）。
3. Streamlit Community Cloud 使用 **Python 3.11**、主程式路徑 `222.py`。此前使用的 `libgl1` 和 `libglib2.0-0` 保留於 `packages.txt`。
4. 若之前已經有 `models/hand_landmarker.task`，繼續保留。若沒有，可在本機從儲存庫根目錄執行 `python scripts/download_hand_model.py`，或由網頁首次分析時自動下載到可寫入的暫存目錄。
5. 網頁版本標記應顯示 `RULA_V11_POSE_QUALITY_REVIEW_2026-10-28`。請使用相同影片先比較 v10.2 和 v11，確認新增 QC 不會誤擋太多正常樣本。

套件**無須新增**：`mediapipe==0.10.21`、`numpy==1.26.4`、`opencv-contrib-python==4.11.0.86` 等沿用既有配置。

## 二、新功能

### P0：逐關節品質檢查

檢查目標側肩、肘、腕、髖的可見度、是否位於影像邊界之外、前臂／上臂的投影比例、左右手腕是否重疊、骨架短縮等情形。Hand 與 Pose 角度差距**不是直接否決 Hand 的理由**。當正面鏡頭未能可靠辨識且啟用了自動補正項目時，分數不能被視為已驗證。

### P1：附近影格重查

只對有疑慮的影格重讀前後約 0.12 秒影格，比對相對軀幹位置。若前後關節位置接近，但中央影格孤立偏離才升級成「需人工複核」。不直接拿前後影格的角度覆蓋當前角度，也不單憑正常快速動作的角度差就剔除。可疑畫面可能需要較多 CPU 時間。

### P2：保守的跨鏡頭品質參考

對已經被標記的影格，額外檢查另一支同步鏡頭對應關節是否更可見；若是，於複核中心提示使用者比較。**不**直接把未經相機標定的另一視角 2D 角度移植到正式 RULA 評分。單側模式的備用鏡頭是正面；雙側模式是另一側。

### 複核與匯出

* 分析完成後的「🧩 剔除樣本」分頁，現在也顯示**骨架品質待複核**資料。左右各自標記、原始影格與骨架照片並排，可疑的肘／腕會加上紅色 QC 圈標示。嚴重異常仍保留候選角度與 Grand Score，避免資料消失。
* 優先只顯示嚴重疑慮；可在第一步的「骨架品質與遮擋篩檢」展開設定切換成審慎模式，使較低風險警示也能列入複核頁。
* 經 QC 分為 **通過／留意／需人工複核**。被標成「需人工複核」的樣本不計入風險總覽的可信統計，直到使用者在剔除樣本分頁明確勾選已目視確認，或在人工修正區重新評分。CSV 原始候選分數與影像保持不動。
* ZIP 新增 `Diagnostics/V11_Skeleton_Quality.csv`、`Diagnostics/V11_Quality_Guide.txt`；品質待複核樣本照片同樣放在 `Diagnostics/Rejected_Images/`。
* 第一頁保留「評估日期、公司／部門、員工／受測者、作業名稱」，ZIP 自動依照這些欄位命名，另附 `作業基本資料.csv`、`作業基本資料.json`。

## 三、測試

在本機（需要 `numpy`）執行：

```bash
python tests/test_v11_quality.py
python -m py_compile 222.py
```

已完成純函式測試與語法編譯；**此環境沒有安裝 MediaPipe 與 Streamlit，所以沒有用真實三台影片在 Streamlit Cloud 做端到端分析測試**。實際部署後請先核對 QC 數量、原圖／骨架、人工確認狀態和 ZIP 是否正確。

## 四、限制與研究注意事項

1. MediaPipe 的 `visibility` 表示模型估計的可見性，**不是角度準確率**。被遮擋時模型仍可能自信地回傳錯誤關鍵點；任何篩檢都不能保證抓到所有錯誤。
2. 前臂／上臂比例來自 **2D 投影**，受到鏡頭角度影響；因此採保守的門檻與多證據判斷。閾值是工程試用值，必須用你的拍攝環境校準。
3. 附近影格分析只能辨識某些孤立跳點，無法可靠區分所有遮擋與真實快速動作。
4. P2 不做多攝影機 3D 標定。三鏡頭若沒有準確同步，其他視角比較也可能錯位。
5. RULA Table A／B／C 仍沿用 v10.2，**尚未完成與標準工作表逐格獨立核對**；不應宣稱已完成 RULA 計分標準驗證。
6. 未經專家檢查，任何輸出的候選分數都不能被當成已證明準確的職業健康評估。
